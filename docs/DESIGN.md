# 设计说明 — 极速开发工具箱（Easy Dev Tools）

> 本文档记录技术与视觉设计约定，供后续迭代轮次遵循。署名：hxd。

## 1. 技术栈

- Vue 3.4 + Vue Router 4 + Vite 5，纯 JavaScript（无 TypeScript）。
- 依赖保持精简：`vue`、`vue-router`、`qrcode`；新增依赖需说明必要性，优先原生实现。
- 工具注册表：`src/router/tools-config.js` 的 `toolGroups` 是工具列表、路由与 SEO 的单一数据源，新增工具只改此处并新增对应视图组件。

## 2. 目录约定

- `src/views/tools/<分类>/`：各工具页面，按 text / converter / generator / crypto / image 分类。
- `src/components/`：跨工具公共组件（布局、工具栏、状态提示、示例/FAQ 等）。
- `src/composables/`：可复用逻辑（如 `useSeo`）。
- `src/config/`：构建期注入的静态配置（如版本信息 `version.js`）。

## 3. 版本与环境

- 版本号以 `package.json` 的 `version` 为准，构建时由 `vite.config.js` 注入为全局常量。
- 环境由构建变量 `VITE_APP_ENV` 决定，取值 `prod` / `test` / `dev`（未设置时为 `dev`）：
  - 生产构建：`VITE_APP_ENV=prod npm run build`，徽标显示如 `v1.0.0`。
  - 测试构建：`VITE_APP_ENV=test npm run build`，徽标显示如 `v1.0.0_test`。
  - 本地开发：徽标显示如 `v1.0.0_dev`。
- 页脚同时展示版本徽标与版权「© <年份> morijiu.cn」。

## 4. 视觉与交互约定

- 风格紧凑现代：常规间距 8/12/16px，卡片圆角 8–12px，按钮高度以 32–36px 为主，避免大留白与大按钮。
- 工具页统一使用公共布局组件，保证输入区、操作区、输出区的位置与行为一致。
- 所有可复制结果提供一键复制与成功反馈；错误输入给出就近的中文错误提示，不弹全局模态。
- 移动端优先保证单列可用、点击目标不小于 40px；桌面端再做多列增强。
- 暗色模式自 R4a 起落地：颜色一律走 `src/style.css` 的 CSS 变量（`--bg` / `--surface` / `--border` / `--text` / `--text-2` / `--text-3` / `--accent-soft` 等），组件内禁止再写死中性色；强调色（`#667eea` 渐变）与成功/危险等语义色可保留。主题由 `src/composables/useTheme.js` 管理（亮 / 暗 / 跟随系统，持久化键 `edt:theme`，生效值写入 `<html data-theme>`），`index.html` 有首屏防闪烁脚本与之保持一致。
- 工具页主容器（`.tool-container`）阴影一律用 `var(--shadow-md)`（R9a 起全站统一）：该变量亮/暗两套主题取值不同（暗色更深），写死 `rgba(0,0,0,0.1)` 类字面量会在暗色下几乎不可见、与其它工具页不一致。
- 中性卡片/浮层阴影同样禁止写死黑色字面量（R9b 起）：小卡片与图片用 `var(--shadow-card)`、hover 与强调浮层用 `var(--shadow-card-hover)`、细边阴影用 `var(--shadow-sm)`，取值均在 `src/style.css` 按亮/暗两套主题定义；强调色渐变按钮的彩色辉光阴影为有意设计，不在此列。
- 代码语法高亮色一律走 `--syntax-*` 变量（R9c 起）：亮色值为 GitHub 亮色口径，暗色值已按暗背景校准对比度（均 ≥6:1）；禁止在组件里写死单主题高亮色——亮色调色板（如 `#005cc5`）在暗背景上对比度只有约 2.6:1。语义徽标背景/文字同样用 `--danger-soft`/`--danger-text` 等成对变量，不写死浅色底（如 `#fee`）。
- CSS 变量引用必须先在 `src/style.css` 定义（R9d 起）：禁止引用未定义变量（如已废弃的 `--text-1`）或靠 fallback 掩盖缺失——`--warning`/`--warning-text`/`--warning-soft`/`--warning-border` 警告色族与 `--on-accent` 已按亮/暗两套主题定义（暗色警告文字 `#fbbf24`，在暗背景上对比度 ≥7.8:1；旧 fallback `#b45309` 在暗色下仅约 2.6–3.5:1）；`--warn-soft` 为既有别名，与 `--warning-soft` 同值保留。页脚统计分隔点等中性元素用 `--text-3`，不写死单主题灰（如 `#cbd5e1` 亮色下对比度仅 1.33:1）。
- 键盘与无障碍自 R5 起落地：命令面板 `src/components/CommandPalette.vue` 全局挂载，`Ctrl+K` / `Cmd+K` 开关、非输入区按 `/` 打开、`Esc` 关闭，支持方向键 + Enter 选择；Header 搜索按钮通过 `edt:open-command-palette` 事件唤起。新增交互控件须带 `aria-label`，键盘焦点统一走全局 `:focus-visible` 焦点环，不要单独移除 outline；页面保留「跳到主要内容」跳过链接（`#main-content`）。表单控件（input/select/textarea）必须有可达名（R9f 起全站 324 个控件已清零）：与可见 `<label for>` 关联、被 `<label>` 包裹、或带 `aria-label` 三者居一；仅有相邻未关联的 `<label>` 文本或 placeholder 不算——placeholder 不是标签。分组字段（如 RGB 三个分量框共用一个组标签）须逐个带 `aria-label` 注明组名与分量。
- SEO 与分享口径（R9e 起）：canonical / og:url 一律本站域名 `https://tools.morijiu.cn` + 工具真实路由路径（`tools-config` 的 `path`），禁止写其它域名或臆造路径（如已废弃的 `easy-dev-tools.com/tools/<id>`）；`og:image` / `twitter:image` 引用的图片文件必须真实存在于 `public/`（`og-image.png` / `twitter-image.png`，1200×630），改引用前先确认文件落地。纯图标/Emoji 按钮（如 📋 复制钮）必须带 `aria-label` 说明动作与对象，屏幕阅读器读不出 Emoji 含义。
- 图片与装饰图标可达名（R9h 起）：与文字相邻的装饰性图标元素（class 含 `icon` 的 span/div，如按钮前的 📝/🗑️/📋、卡片与分组图标、About 的 section-icon）一律加 `aria-hidden="true"`，避免屏幕阅读器把 Emoji 名逐个念出、与相邻文字重复；纯图标按钮（内容只有图标/符号、如 Markdown 工具栏与逐条 📋 复制钮、图片移除 ×）必须带 `aria-label` 说明动作与对象，仅有 `title` 不算可达名。品牌 Logo 图片与相邻品牌名文字并存时 `alt=""`（装饰），避免同一名称读两遍；有内容的图片 `alt` 用中文描述内容（如「生成的二维码图片」），不用英文占位。普通元素（如无 role 的 div）上的 `aria-label` 不会被读出，不要用它代替 `aria-hidden` 或真实文本。
- 状态消息必须可播报（R9k 起）：全站状态反馈走共享组件 `ToolStatusMessage`（72 个工具页共用），组件按类型给出 live region 语义——错误用 `role="alert"` + `aria-live="assertive"`、成功/信息用 `role="status"` + `aria-live="polite"`，均带 `aria-atomic="true"`，屏幕阅读器才会主动念出「成功/失败」结果；禁止只靠颜色与视觉出现传达状态。自带的状态段落（如哈希校验结果）同样须带 role/aria-live。各工具自带的动态提示条（计算后才出现的 notes/warnings/截断与处理提示，R9l 起）统一带 `role="status"` + `aria-live="polite"`，让「已自动处理/需要注意」类信息也能被读屏播报；静态说明文字（常驻的格式提示、字段说明）不加 live region，避免进页即朗读。
- 自动移动内容必须可暂停（R9j 起）：持续自动滚动/移动超过 5 秒的内容（如首页工具弹幕 Danmaku）必须提供暂停/继续开关（带 `aria-pressed` 与 `aria-label`），且鼠标悬停、键盘焦点进入区域时自动暂停（`animation-play-state: paused`），方便点中与读清移动中的链接；系统 `prefers-reduced-motion: reduce` 时默认静止——组件内显式 `animation: none` 并默认暂停，不要只依赖全局规则压缩动画时长（那会跳到末帧而非停在起点）。
- 披露菜单须多通道可操作（R9i 起）：Header「全部工具」下拉一类的展开菜单禁止只靠鼠标悬停打开——触发按钮必须可点击切换、带 `aria-expanded` 与 `aria-controls` 指向菜单，并支持 Esc 关闭并回焦、焦点离开区域自动关闭、点击外部关闭、路由变化关闭；悬停只作鼠标用户的快捷方式，不能是唯一入口（触屏与键盘用户没有 hover）。
- 示例区可达名（R9m 起）：共享组件 `ToolExamples` 的标题与按钮内装饰 Emoji（📝/🚀）须用 `<span aria-hidden="true">` 包裹（同 R9h 口径，不限于 class 含 icon 的元素）；同页多个「使用此示例」按钮的可达名禁止完全相同——按钮须带含示例序号与说明的 `aria-label`（如「使用示例 1：格式化 JSON」），屏幕阅读器与语音控制用户才能区分要触发哪一个。共享组件卡片网格列宽用 `minmax(min(<列宽>, 100%), 1fr)`，不裸写 `minmax(300px, 1fr)` 以防窄容器溢出（同 R7d 口径，`ToolExamples`/`ToolFeatures` 已统一）。
- 二级文字与语法键名对比度（R9q 起）：`--text-2` 是全站正文级次要文字（说明、统计、FAQ 答案等），取值必须在主背景（surface/bg/bg-soft）上 ≥4.5:1 且层级不得倒置——亮色旧值 `#6b7280` 在 bg-soft 上仅 4.35:1，且 R9o 把 `--text-3` 校准到 `#646c78` 后反而比它更深、二级/三级层级倒置，现亮色 `--text-2` 改 `#565e6a`（三主背景 5.89–6.55:1、亮度低于 `--text-3`，层级恢复）；暗色 `#9aa3b2` 本就达标且浅于暗色 `--text-3`，未动。语法高亮键名色同理须 ≥4.5:1：亮色 `--syntax-key` 旧值 `#e36209` 在 surface 上仅 3.49:1，现改 `#bc4c00`（surface/bg-softer/bg-soft 4.53–5.03:1）；其余语法色与暗色键名 `#ffab70`（8.77:1）已达标未动。
- 三级文字对比度（R9o 起）：`--text-3` 被页脚、提示、统计、行号、placeholder 等小字广泛用作正文色，取值必须在两套主题的主背景（surface/bg/bg-soft）上均 ≥4.5:1——亮色 `#646c78`（旧值 `#9ca3af` 仅 2.28–2.54:1）、暗色 `#8b94a5`（旧值 `#6b7280` 仅 3.03–3.91:1）；不得为「更淡的灰」调浅，层级感靠字号与字重拉开，不靠牺牲对比度。
- 强调/语义文字对比度（R9p 起）：`--accent` 与 `--accent-2` 只作背景、渐变、边框与图标底，禁止直接作文字色——`--accent` 作文字亮色仅 3.33–3.66:1、暗色在 `--accent-soft` 上仅 3.74:1，`--accent-2` 暗色仅 2.56:1。文字一律走 `--accent-text`（亮 `#4a54c4` / 暗 `#93a5f5`）与悬停 `--accent-text-hover`（亮 `#764ba2` / 暗 `#c9a7eb`），两套主题主背景上均 ≥4.5:1；成功/危险小字同理走既有的 `--success-text` / `--danger-text` 成对变量，不直接用 `--success`（亮色仅 2.55–2.87:1）/ `--danger`（亮色仅 3.82:1）作文字色（作背景/强度段填充不受此限）。
- 强度文字对比度（R9r 起）：密码生成器的强度结论文字（弱/中/强）禁止写死鲜艳语义色作文字——旧值 `#e74c3c`/`#f39c12`/`#27ae60` 在亮色 `--bg` 上仅 3.62/2.08/2.73:1；一律改走成对语义文字变量 `--danger-text`/`--warning-text`/`--success-text`（两套主题在 `--bg` 上均 ≥4.76:1）。强度条填充色（`.strength-fill`）是与文字并存的图形填充，可保留鲜艳色，不受此限。
- 实心强调底对比度（R9t 起）：纯色 `--accent`（`#667eea`）底配白字仅 3.66:1，不达 AA——凡纯色强调底承载白字/`--on-accent` 文字（主按钮、模式/选中态 chip、`::selection`、悬停变实心底等）一律走 `--accent-solid`（`#4a54c4`，白字 6.26:1，两套主题共用，暗色不另设浅值以免白字反而不达标）；`--accent` 本体只作渐变、边框、图标底、滑杆/圆点等图形填充，渐变按钮（`--accent`→`--accent-2`）为有意设计保留。
- 渐变与成功底对比度（R9u 起）：渐变底承载白字时按最浅一端算对比度——`--accent`→`--accent-2` 渐变浅端白字仅 3.66:1，凡渐变底承载白字（编辑面板头、示例按钮/序号徽标、当前时间卡片、选中态页签、图片主操作按钮、About 页背景等）一律走 `--accent-grad-from`（`#4a54c4`）→`--accent-grad-to`（`#764ba2`），两端白字均 ≥6.2:1；预览面板头绿渐变走 `--preview-grad-from`/`--preview-grad-to`（旧值 `#11998e`→`#38ef7d` 白字仅 3.52/1.52:1，新组两端 ≥5.4:1）；纯色 `--success`（`#27ae60`）底配白字仅 2.87:1，承载白字的成功底（下载按钮、成功徽标、节省徽标）一律走 `--success-solid`（`#1e7e34`，白字 5.14:1）；不承载文字的装饰渐变（图标底、Emoji 钮底）与图形填充（强度段）不在此列。
- 语义文字残留清零与实心危险底（R9v 起）：R9p 已立「成功/危险小字走 `--success-text`/`--danger-text`」规矩，但仍有残留直接以 `color: var(--danger, …)` / `color: var(--success, …)` 作文字色（实际渲染 `--danger` `#e74c3c` 亮色主背景仅 3.43–3.82:1、暗色 surface 仅 4.26:1；`--success` `#27ae60` 亮色仅 2.73–2.87:1），现 40 处全部清零迁移到成对文字变量（两套主题主背景均 ≥4.5:1，危险文字最低 9.63:1、成功文字最低 8.23:1）；禁止再用带 fallback 的 `var(--danger, …)`/`var(--success, …)` 写文字色（边框/图形填充不受此限）。纯色 `--danger` 底配白字同理仅 3.82:1，承载白字的危险底（图片移除钮悬停）一律走 `--danger-solid`（`#c0392b`，白字 5.44:1，两套主题共用）。
- 语义文字与变量 fallback 残留清零（R9w 起）：R9p/R9v 立规后仍有残留——2 处文字色直接用 `var(--accent, …)`（时区跨日标记、JSONPath 路径，实际渲染 `#667eea` 亮色仅 3.66/3.47:1、暗色 surface 仅 4.45:1，均不达 AA）改走 `--accent-text`（亮 6.26:1 / 暗 6.93:1）；3 处警告文字直接用 `var(--warning)` 改走成对的 `--warning-text`（两变量当前同值、无视觉变化，但文字必须走 -text 变量以防日后分化时静默不达标）；全站带十六进制 fallback 的 `var(--x, #…)` 引用清零（共 15 处含边框/背景，相关变量均已在 `src/style.css` 双主题定义，fallback 只会掩盖变量缺失、且旧 fallback 值与现行变量不一致）——禁止再写 `var(--…, #…)` 形式的样式引用。
- 页脚链接与收藏星标对比度（R9s 起）：页脚链接文字禁止写死鲜艳色——普通链接悬停旧值 `#3b82f6` 在页脚背景上仅约 3.5:1、「支持」高亮 `#f59e0b`/`#d97706` 仅 2.15/3.19:1、开发者链接 `#8b5cf6` 仅约 3.9–4.23:1，现分别改走 `--accent-text` / `--warning-text` / `--accent-text-hover`（悬停 `--accent-text`），两套主题页脚背景上均 ≥4.5:1；渐变下划线与图标底等装饰背景不受此限，页脚爱心 `#ef4444` 为装饰字形（≥3:1 图形口径）保留。收藏星标是收藏状态的唯一视觉指示，须 ≥4.5:1：一律走 `--favorite-star`（亮 `#b45309` / 暗 `#f5a623`），禁止写死 `#f5a623`（亮色仅 2.03:1）。
- 焦点环不得被压制（R9y 起）：控件的 `:focus` 规则与滑杆/可聚焦区的基础规则禁止写 `outline: none`——其特异性高于全局 `:focus-visible` 焦点环，会让键盘焦点只剩边框变色甚至毫无提示（R9y 清理 19 处，分布 11 文件：各工具 `:focus` 规则、二维码/图片工具的 range 滑杆基础规则、按键捕获区基础规则）；`:focus` 只改边框/背景色，全局焦点环负责键盘可见性。仅三处有意保留：全局 `button` 元素级重置（特异性低于 `:focus-visible`、不压制焦点环）、首页搜索框与命令面板输入框两个无边框输入框（本身无边框可描，焦点提示由容器 `:focus-within` 变色承担——搜索框容器原本已有、命令面板输入行 R9y 补齐）。
- 共享小节组件紧凑规格（R9x 起）：`ToolFaq` / `ToolUsageGuide` / `ToolFeatures` 三个全站共享小节的标题统一 `1.3rem` 左对齐、小节顶部间距 28–32px、卡片/容器内边距 12–20px、条目间距 8–10px（旧值标题 1.8–2rem、顶部间距 40–50px、内边距 25–30px 与紧凑口径脱节，且三组件规格互不一致）；新增共享小节组件照此规格，不再放大标题与留白，层级感靠字重与边框拉开。
- 整卡导航用真链接（R9z 起）：可点击的卡片禁止用「容器 @click + tabindex + keypress」模拟链接——空格键不触发、读屏只念容器不念可操作元素、且会与卡内按钮构成嵌套交互。首页工具卡片改拉伸链接模式：标题内放真实 `<router-link>`，其 `::after` 覆盖整卡承担点击区，卡片键盘焦点环由 `.tool-card:focus-within` 在整卡上绘制（链接自身 outline 在此模式下关闭，属 R9y 例外——焦点提示由整卡环承担）；卡内独立操作（收藏按钮）须包一层 `position: relative; z-index: 1` 的容器浮到覆盖层之上、保持可点。新增整卡导航照此模式。
- 上传/拖放区必须键盘可操作（R9aa 起）：点击打开文件选择器的上传/拖放区禁止只靠鼠标点击——须带 `tabindex="0"`、`role="button"` 与说明用途的 `aria-label`，回车与空格均须与点击等效（空格在 keydown 拦截默认滚动），并有 `:focus-visible` 焦点环。二维码解码区此前只有回车、缺空格，现已补齐；图片压缩/图片转换/哈希文件三区此前完全不可聚焦，现已统一。键盘处理须先判事件来自区域本身（`e.target === e.currentTarget`），区内嵌套按钮（如图片转换的「载入示例图片」）由其原生键盘行为处理、不重复触发文件选择。新增上传/拖放区照此办理。
- 模态对话框必须带焦点陷阱（R9ab 起）：标了 `aria-modal="true"` 的对话框（如命令面板）打开后 Tab / Shift+Tab 只能在面板内可聚焦元素间循环、不得逃到被遮罩覆盖的背景页；Esc 须在面板内任意焦点位置都能关闭（另加全局 Esc 兜底，焦点万一在面板外时也能关），关闭后焦点回到打开前的元素。仅靠 `overflow: hidden` 锁滚动不算焦点管理。新增模态照此办理。
- 模式切换禁用 tab 语义（R9ac 起）：工具内的模式/方向切换（互斥按钮组、切换后下方内容随之更新、无独立面板与方向键导航）不是标签页界面，禁止用 `role="tablist"`/`role="tab"`/`aria-selected`——tab 语义要求配 `tabpanel` 与左右方向键切换，只标不用会误导读屏（R9ac 清理 8 处：Env/JSON、JSON/CSV、TOML/JSON、YAML/JSON 互转、哈希输入模式、cURL 代码类型、Unicode·HTML 模式、JSON 转义模式）。正确口径：容器 `role="group"` + `aria-label`，每个按钮带 `:aria-pressed` 与 `.active` 同步，让选中状态可播报；命令面板列表的 `aria-selected`（listbox/option 语义）不受此限。新增模式切换照此办理。此口径同样适用于一切带 `.active` 视觉选中态的按钮（R9ad 补齐 30 处模板：分类/筛选 chips、模式与视图切换、预设与前缀 chips，以及哈希算法多选与大小写开关等真切换按钮）——只要视觉上呈现「已选中/已开启」，就必须同步 `:aria-pressed`，不得只靠颜色传达；纯动作按钮（示例/预设载入且无 `.active` 态者）不加。
- 标题层级与地标（R9g 起）：全站只有一个 `<main>`（`MainLayout` 的 `#main-content`），页面与工具组件禁止再嵌套 `<main>` 或 `role="main"`，根元素用 `<div>`。标题不得跳级：页面 `<h1>` 后的一级小节用 `<h2>`（含页脚栏目名、编辑面板标题与各工具的结果/设置小节），`<h3>` 只用于 `<h2>` 之下的子项（如功能特点卡片）；改标题级别时同步改对应 CSS 选择器并靠 class 固定字号，不靠标签默认字号。多个 `<nav>` 并存时每个都要有 `aria-label` 区分（主导航 / 分类快速导航）。

- 同名复制按钮可达名须区分对象（R9ae 起）：结果表格/列表里逐行出现的「复制」按钮禁止可达名完全相同——每行须带含行名/对象标识的 `aria-label`（如「复制网络地址」「复制状态码 404 Not Found」「复制时间戳（秒）」），屏幕阅读器与语音控制用户才能区分复制的是哪一行（同 R9m 示例按钮口径）。R9ae 已补齐 27 处、分布 19 个工具页；页面内唯一的「复制全部/复制摘要」类按钮本身已自带对象说明，不在此列。新增逐行复制按钮照此办理。
- 表格表头必须带 scope（R9af 起）：所有 `<th>` 必须声明作用域——`<thead>` 内的列头用 `scope="col"`、行首的行头用 `scope="row"`，屏幕阅读器才能把数据单元格与行/列头正确关联（无 scope 时只能靠位置猜测，键值表与多列表格都会读错对应关系）。R9af 已补齐 73 处、分布 20 个工具页（此前仅 Cron/Base/JWT/正则 4 页已带 scope）；新增表格照此办理。
- 循环行内控件可达名须带行标识（R9ag 起）：`v-for` 循环生成的每一行/每一层里的表单控件与删除按钮，`aria-label` 必须带行序号或行标识（如「第 2 个色标取色器」「第 1 层水平偏移」「删除第 3 个参数」），禁止多行共用完全相同的静态可达名——R9ae 只覆盖了复制按钮，取色器/滑杆/数值框/参数输入框/行删除按钮同理。R9ag 已补齐 19 处、分布 3 个工具页（CSS 渐变色标行 5、CSS 阴影层卡 11、URL 解析参数行 3）；新增循环行控件照此办理。R9ah 续补循环内操作按钮 7 处、分布 5 个工具页：密码/UUID 逐条复制带序号、图片压缩/转换的每图压缩·转换·下载按钮带文件名、哈希结果卡 Aa 大小写切换带算法名——循环生成的按钮（不只表单控件）同样禁止共用相同可达名。

## 5. 构建与发布纪律

- 构建后必须单独核验退出码（日志落文件后检查），不得用管道掩盖构建失败。
- 测试与生产使用同一份代码、不同构建变量；先在测试环境验收，再谈生产发布。
- 单页应用需保证深路径可直接访问（静态托管侧做 SPA 兜底）。
